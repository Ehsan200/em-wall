# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Common commands

```bash
make test                # core unit tests (no root, no port 53)
go test ./core/rules/... # run tests for a single package
go test -run TestX ./core/decision  # single test
make run-daemon          # local daemon: ./tmp/dev.db, ./tmp/em-wall.sock, :5353, system DNS untouched
make run-app             # Wails dev UI; stages embedded resources first (separate terminal)
make daemon              # builds build/em-walld
make cli                 # builds build/em-wall (command-line client)
make app-bundle          # primary user-facing build: stages resources + `wails build` → app/build/bin/em-wall.app
make tidy                # `go mod tidy` in both modules
```

Install/uninstall happens from inside the .app — see "In-app install / uninstall" below. The `em-wall` CLI ships as another embedded resource of that installer, so it has no install path of its own either.

The repo is a **Go workspace** (`go.work`) with two modules: the root module (daemon + core/) and `app/` (Wails UI). Use `go work` semantics — running `go test ./...` from root only sees the root module; the app module has its own `go.mod`. Frontend lives in `app/frontend` (Vite + Vue 3 + TS); `wails dev` handles its build.

## Architecture

This is a macOS firewall built around **DNS-layer interception**. There are two binaries that talk over a Unix socket:

- **`daemon/` → `em-walld`** — privileged process (LaunchDaemon, root). Owns the SQLite store, runs the DNS proxy on `127.0.0.1:53`, manages per-host routes via `/sbin/route`, and exposes the IPC server. Wires `core/*` packages together.
- **`app/` → Wails app** — unprivileged user-launched UI. Pure thin client; every `App` method on [app/app.go](app/app.go) just forwards an IPC call. **All real work lives in the daemon.**
- **`cli/` → `em-wall`** — unprivileged command-line client, installed to `/usr/local/bin` by the same in-app installer. Also a pure thin client (`status`, `health`, `rules`, `group` subcommands); it never opens the DB. The socket is mode 0660 group `staff`, so no `sudo`. Exit codes are part of its contract: `0` ok, `1` daemon-side error, `2` usage, `3` unreachable. Subcommand flags parse via `parseFlags` in [cli/main.go](cli/main.go), which permutes so flags may follow positionals — the stdlib `flag` package otherwise stops at the first non-flag word.

The IPC protocol is **newline-framed JSON-RPC** over `/var/run/em-wall.sock`. The single source of truth for method names and payload shapes is [core/ipc/protocol.go](core/ipc/protocol.go) — adding a feature means: define DTO + method constant there, register handler in `daemon/main.go` `registerHandlers`, expose method on `app/app.go`. The Wails frontend gets a typed binding for free via `wailsjs/`. Surfacing the same feature in the CLI is optional and independent — `cli/` reads the DTOs directly from `core/ipc`, so it needs no generated bindings.

### `core/` is intentionally OS-agnostic

The OS-coupled bits (`dnsproxy`, `routing`, `pfctl`) are isolated behind interfaces; `rules`, `decision`, `groups`, `ipc` are pure Go.

```
core/rules       — GORM+SQLite store, wildcard matcher (`*.x.com` matches apex + subs)
core/decision    — Engine: caches rule list (atomic.Pointer), Decide(name) → block/allow/route
core/dnsproxy    — UDP+TCP server on miekg/dns; takes Decider, Forwarder, Routes, Proxies via interfaces
core/routing     — Per-host route installer; sweeps expired entries on TTL
core/pfctl       — Manages an `em-wall` pf anchor for DoH/DoT blocking
core/groups      — Curated bundles of patterns ("Anthropic", "OpenAI") for one-click rules
core/ipc         — JSON-RPC over Unix socket; protocol.go is the wire contract
```

### Decision flow per DNS query

1. `decision.Engine` finds the most-specific matching rule (`rules.MostSpecific`): exact > wildcard at same depth; ties broken by lower ID.
2. **Block** → return NXDOMAIN with negative-cache TTL.
3. **Allow** with no interface → forward upstream as normal.
4. **Allow/Route** with `Interface = "utunN"` → forward, then for each A/AAAA in the answer, install `route -host <ip> -interface utunN`.
5. **Route** with `Interface = "proxy:NAME[,...]"` / `"xray:NAME[,...]"` → resolve to the daemon-owned proxy utun (`cfg.ProxyTun`), serve a fake IP (FakeIP), pin it there, and record the IP → (proxyNames, hostname) mapping so the netstack TCP layer redials through the chosen upstream proxy. (The old `app:KEY` binding — resolve a VPN app's utun via lsof — was removed; it broke whenever a VPN app hijacked DNS. proxy:/xray: supersede it. The daemon hard-deletes any leftover `app:` rules on startup.)

Rule changes via IPC always call `engine.Reload(ctx)` after a store mutation; updates and deletes also call `router.RemoveByRule(id)` so per-host routes don't outlive their binding.

### System DNS hijack lifecycle

The daemon may put `127.0.0.1` into every network service's DNS. This is risky — losing DNS bricks all networking — so `activateSystemDNS` in [daemon/main.go](daemon/main.go) is defensive:

- Captures the pre-hijack per-service DNS into `system_dns_backup` (sanitized: loopback entries become "DHCP-supplied" so restore returns to Empty, not 127.0.0.1).
- Picks an upstream from a priority list (per-service manual → backup → `AllDHCPDNS` across non-tunnel ports → `scutil --dns` → 1.1.1.1/8.8.8.8) and **validates each candidate with a live query**.
- Refuses to activate if no candidate answers, even falling back to deactivating if we were stuck in a 127.0.0.1-only state from a prior bad run.

`AllDHCPDNS` (in [daemon/system_dns.go](daemon/system_dns.go)) exists specifically because when a VPN owns the default route, `scutil --dns` only sees the VPN-pushed resolver, which may be loopback or unreachable from the daemon.

### In-app install / uninstall

The installer is the **only** install path — there is no shell script counterpart. The flow lives in [app/internal/installer/](app/internal/installer/):

- The daemon binary, plist, and pf anchor stub are embedded into the Wails binary via `//go:embed all:resources`. The Makefile target `app-resources` populates that directory before `wails build` (or `wails dev`) runs. A `wails dev` build without it will set `IsPackaged()` false and the install panel will refuse to act.
- `installer.Install` extracts the embedded files into a temp dir, writes a bash script with the install steps inlined, and runs it via `osascript ... do shell script "..." with administrator privileges`. macOS shows the standard auth prompt; cancellation surfaces as `installer.ErrCancelled`, which `App.Install`/`App.Uninstall` translate into a literal "cancelled" error so the frontend can ignore it silently.
- `App.Uninstall` first asks the still-running daemon (over IPC) to deactivate the system DNS hijack so the daemon's saved per-service backup restores the *original* DNS. The uninstall script then runs a safety sweep at the very end: any service whose first DNS entry is still `127.0.0.1` is reset to DHCP-supplied, then `dscacheutil -flushcache` and `killall -HUP mDNSResponder` are invoked. This is the last line of defence against leaving the host with broken DNS if the deactivate IPC failed (daemon already crashed, lost backup, etc.). The Settings → Uninstall section requires typed confirmation (`uninstall` or `delete everything`) and offers a purge toggle for the rules DB and log file.
- `App.InstallStatus` (filesystem inspection) is local to the UI process — no IPC. The install panel polls it; daemon-side `Status()` is the regular IPC call that fails until the daemon is running.

## Conventions

- `Rule.Action` is one of `block`, `allow`, `route`. `route` requires non-empty `Interface`; `allow` requires empty.
- `Interface` field accepts a literal interface name (`utun3`), `proxy:NAME` / `proxy:NAME1,NAME2`, `xray:NAME` / `xray:NAME1,NAME2` (multi-name fallback, first available wins), or `xrayset:NAME` (see below).
- **Outbound sets** (`core/xray/set.go`, `core/xray/set_store.go`) are named, ordered bundles of outbounds — typed members `xray:a,proxy:b` — that a rule binds to as a unit via `xrayset:NAME`. The rule stores only the reference, so editing a set's membership reaches every rule bound to it with no migration (the opposite of curated groups, whose patterns are copied into rules). `decision.Engine.Reload` resolves the indirection once per reload through the `InterfaceExpander` interface (satisfied by `*xray.Store`), so `Decision.Interface` is always literal and nothing downstream — dnsproxy, proxytun, routing — knows sets exist. An all-xray set expands to `xray:a,b,c`; a set with any plain proxy member expands to `proxy:_xray_a,b` instead. Daemon readers that inspect stored rule rows directly (`reconcileIPRoutes`, `exitip`, `proxylatency`) expand for themselves via `handlerDeps.expandIface` / `expandRuleIfaces` in [daemon/xray_sets.go](daemon/xray_sets.go). A disabled or deleted set is left out of the expansion map, so its rules keep the raw `xrayset:` string and fail closed (NXDOMAIN) rather than leaking to the default route; a **disabled xray member** is dropped from its set's expansion for the same reason (its SOCKS inbound isn't running, so every dial to it is a guaranteed wasted attempt that also drops the destination's sticky binding), and a set left with no usable member is omitted entirely. A member whose entry is *missing* is kept — that's a broken ref the UI flags, not an off-switch. Renaming an xray entry or proxy cascades into set membership; deleting one is refused while a set still names it.
- Disabled rules are skipped during matching, not deleted. `decision.Engine` compiles the rule list into a `rules.Index` (exact/wildcard maps + IP list) at `Reload`; `rules.MostSpecific` is the reference semantics and `TestIndexMatchesLinear` keeps them equal.
- `proxy.Store.GetByName` is served from an in-memory copy invalidated on every write — it is on the DNS and per-connection hot path, and the store has a single SQLite conn. Proxy rows must only be written through `proxy.Store` methods.
- Masters whose `Dialer` names the same refs share one dialer slot (`DialerSlot.Aliases`): one set of member outbounds, one balancer, one set of observatory probes, but each master keeps its own `dialer-NAME` outbound.
- A connection that sent bytes and got nothing back strikes its upstream only if another upstream carried data within `uplinkWitnessWindow` ([daemon/uplink_witness.go](daemon/uplink_witness.go)); otherwise it's the local uplink and blaming the member demotes whole sets in lockstep.
- **Multi-outbound selection is sticky, and a successful dial proves nothing.** An xray entry is a loopback SOCKS5 inbound, and xray answers CONNECT with success *before* dialing the far side — so a dead node dials fine and `dialBinding`'s fallback list would never advance. Two things compensate, both in [daemon/proxytun.go](daemon/proxytun.go): on client-speaks-first ports the client's TLS ClientHello is forwarded and a reply byte required, and members are **raced, not walked** (`raceRound`): the best-ranked starts alone, a sibling starts beside it after `proxyHedgeDelay` (max `proxyHedgeMaxInFlight`), the hello is replayed, first reply wins — a serial walk spent the whole connect deadline on stalls; members that failed are struck only if a sibling carried the connection (a total failure is the uplink or the destination, and blaming every member demotes the whole set in lockstep — the prober drops all-fail rounds for the same reason); and a connection that ends with bytes sent and none received strikes the upstream in the `netprobe.LatencyTracker`, which demotes a name on a consecutive-failure streak or a failure rate (see the flaky-upstream bullet below). Selection itself is keyed per destination hostname, then site (`stickyKeys`, `stickyBindings` in [daemon/proxysticky.go](daemon/proxysticky.go)) and fed to `RankFrom` as the incumbent, so a site keeps one member unless it dies or another is better by both hysteresis margins. Healthy members are ranked by an effective cost, not raw RTT (`sample.cost`: rtt × (1 + `failRateWeight` × failure rate) + a `recentFailPenalty` fading over `recentFailWindow`), so on close pings the member that has not been dropping connections wins. Without stickiness a single page load scatters across exits and origins treat it as a hijacked session. **Carrying one connection does not take a site over** (`settleBinding`): a hedge win or a carry during a brief outage leaves the binding alone; it moves only when the incumbent leaves the binding, loses its seat (`netprobe.Seat`: breaker open or down past `SeatGrace`), is ranked behind a working member on purpose (margin / siteAvoid), or misses the site `stickyMoveMisses`× over `stickyMoveAfter` with no carry between — rebinding on every blip moved sites to a new exit every few minutes on a flapping pool. One failure keeps an incumbent first (unknown tier is held), and a traffic `Fail` no longer flips `ok` — only probes do. Moves are counted as `rebinds` (Health tab "Exit switches", `em-wall health`) and logged with a reason. Healthy members are ranked on the **median of the last `rttSamples` probe RTTs** (one probe on a lossy uplink reads 10× the next), and a member with an outage or breaker edge within `probationWindow` sits in a **probation tier** behind steady members — without it a member just back from an outage won the ranking on one low probe, took sites over, dropped out again and handed them back every 30–60s.
- **Telegram (MTProto) is verified like TLS.** Telegram reaches its DCs by IP on 443/80/5222 with the obfuscated2 transport, not TLS, so it used to be forwarded unverified — the first-ranked member was used blindly and a dead exit swallowed every Telegram connection (then tcpHealth paused the DC IP). `looksLikeMTProto` ([daemon/mtproto.go](daemon/mtproto.go)) recognises the 64-byte header exactly (it carries its own AES-CTR key/IV; the decrypted bytes 56–60 are the transport tag), and a header with its first packet goes through `raceRound` like a ClientHello. `clientSpeaksFirst` includes 80 and 5222 for this. A client silent past `proxyClientHelloWait` is forwarded unverified, not killed (Telegram and browsers open spare connections), and one that closes before sending (`errClientGone`) never strikes the destination. Likewise a connection the client closed first within `proxyAbandonWindow` with no reply (`proxy.SpliceObserved` → `AFirst`/`FirstEnd` — measured at the client side's end, since xray holds the downlink ~5s after a FIN) is an abandoned happy-eyeballs race, not a path failure: Telegram dials its DC on three ports at once and drops the losers, and blaming the member for each demoted every member it rode on.
- **A failing destination must cost less on each retry, not the same.** Nothing rate-limits a client, and a dead exit that accepts connections means every retry pays for a full `dialBinding` walk (up to `proxyDialMaxRounds` × binding size, held for `proxyConnectDeadline`). Observed: 6308 connections to one host in two minutes, two pegged cores and ~1300 threads across `em-walld` and `xray`. Three brakes, all in `daemon/`: `tcpHealth` ([daemon/tcp_health.go](daemon/tcp_health.go)) pauses a destination after `tcpStrikeThreshold` total failures — the TCP twin of `udpHealth`, but it admits one probe per `tcpProbeInterval` so recovery is seen in ~1s and a single byte received clears the record; `dialGate` ([daemon/dialgate.go](daemon/dialgate.go)) caps concurrent dials and **must be released before the splice** (a long-lived stream holds no dial resources and must never starve new connections); `logSampler` ([daemon/logsample.go](daemon/logsample.go)) rate-limits the per-connection log line, since `log.Logger` serialises every caller on one mutex and a connection storm otherwise becomes a thread storm through the logger alone. Any new per-connection log line goes through the sampler.
- **A flaky upstream is worse than a dead one, and only a failure RATE catches it — but a dead one must come back the moment it answers.** `netprobe` ([core/netprobe/latency.go](core/netprobe/latency.go)) keeps two separate verdicts per name. An **outage** (`deadStrikeThreshold` consecutive failures → *suspect*, shown as `down`) ranks the name behind healthy and unknown members and ends on the very next success — probe or carried connection — and its failures are then removed from the rate window, so a node that was down and suddenly works is back in its set within one fast probe (~10s) instead of sitting out a cooldown. The **circuit breaker** (*demoted*) is for the nodes the streak can't catch: it opens on a failure rate (`breakerOpenRate` over `breakerMinSamples`, weighed only outside an outage, and only when `breakerRelativeMargin` worse than the median of the other names — on a lossy uplink every member fails together and an absolute threshold demoted them all) or on flapping (`flapOutages` outages within `flapWindow`; an outage that starts while half the other names are also down is the uplink and isn't counted), and closes once its cooldown has passed AND the window is clean (`breakerCloseRate` + `breakerCloseStreak`). The cooldown doubles per repeat trip (`breakerCooldown` → `breakerCooldownMax`, forgotten after `breakerTripMemory` quiet), so a node that blipped once is back fast and a chronically bad one stays out longer. Suspect and demoted names are ordered least-bad first (failure rate, then last RTT), so when everything is down the best bet goes first. The prober runs a full round every `proxyProbeInterval` and re-checks only `Unsettled` names every `proxyProbeFastInterval`. Each round is a **URL test** (`netprobe.MeasureURL`: plain HTTP GET `cp.cloudflare.com/generate_204` through the member, timed to the status line, success only on 204 — the "real delay" V2Box/Hiddify show), run `proxyProbeAttempts` (3) times per name with every attempt recorded: one TLS-handshake attempt per round showed a member that failed 2 of 3 tests as "372ms ok", and kept a one-off 6s reading as a good member's RTT. Probing only runs for names bound alongside another — a single-member set is never probed, raced or ranked. After `Reset` (network change / wake) failures are dropped for `resetGrace` — the reset fires before the new network works. Other load-bearing asymmetries: open and close thresholds differ (equal ones chatter), and traffic-observed outcomes (`Fail`/`Succeed`) enter the window at most once per `trafficSampleInterval` per name while still counting in full toward the streak — otherwise one client retry storm against one dead destination would demote an upstream that carries everything else fine. Edges are logged by the `OnBreakerChange` / `OnSuspectChange` hooks wired in `daemon/main.go`.
- The daemon's own log is written by launchd (`StandardOutPath`), so it can't be handed to a rotating writer — `rotateDaemonLogIfTooLarge` ([daemon/logrotate.go](daemon/logrotate.go)) trims it in place to its last `daemonLogKeepBytes`, on the same one-minute tick as xray's log cap.
- **xray is never restarted for a routine change.** `xraySupervisor.Reconcile` diffs the new generated config against the one the process is running (`running`) and applies it through the xray API ([daemon/xray_live.go](daemon/xray_live.go)): inbounds/outbounds replaced by tag (`adi`/`rmi`/`ado`/`rmo`), routing — rules *and* balancers — swapped whole (`adrules` without `-append` replaces). A restart drops every connection through every entry, so it is reserved for changes outside those sections (log, api, policy, observatory) or an API failure. Invariants that keep this possible: the API inbound and burst observatory are always emitted, blackhole is always the FIRST outbound (xray's default for unmatched traffic can't be moved live), and `SyncDialerMembers` is just `Reconcile`. xray logs are truncated in place (O_APPEND), never rotated by restart. `TestLiveApplyKeepsUntouchedStreams` runs the real binary — build the supervisor struct by hand there, `newXraySupervisor` kills every `em-wall-xray` process.
- **A live apply leaves open streams on the old path — stalled ones are closed, healthy ones never.** xray does not close an in-flight connection when its outbound is removed (`rmo`) or replaced — verified against the real binary in `TestStalePathAfterLiveDialerChange` — so a stream on a member that was parked or dropped hangs up to `connIdle` (30 min). After every successful `applyLive`, `changedPathEntries` ([daemon/stalepath.go](daemon/stalepath.go)) turns the removed/replaced tags into entry names (`out-`/`in-`/`dialer-` NAME, and every master of an old slot that lost a `slotN-out-` member) and `liveConns.markStale` flags their open splices; the sweeper closes a stale splice only once the client's bytes have gone unanswered for `stalePathStallTimeout`, so the app reconnects onto the new path. Don't close all stale connections outright: a master's exit is its own server whichever member carries it, so moving a working stream gains nothing. Closing is per entry, not per slot port (the Linux `ss -K` approach), because the daemon owns both ends. A restart needs none of it. UDP isn't tracked — its own no-reply watchdog (`proxyUDPNoReplyTimeout`) already covers it.
- **Mux is a per-entry opt-in** (`xray.Config.Mux`, [core/xray/mux.go](core/xray/mux.go)): Generate adds a mux.cool block only where `MuxSupport` allows — VMess/VLESS(no XTLS flow)/Trojan over non-multiplexing transports (not gRPC/XHTTP/H2/QUIC), never over a user-written `mux` block — with `xudpProxyUDP443: skip` so QUIC's path is unchanged. The DTO's `muxNote` carries the reason it doesn't apply. `TestMuxSharesTunnels` checks against real xray that 5 streams use 1 server connection.
- **Fragment is a per-entry opt-in** (`xray.Config.Fragment`, stored JSON of packets/length/interval; [core/xray/fragment.go](core/xray/fragment.go)): Generate chains the entry's dial through a freedom outbound carrying `settings.fragment` via `sockopt.dialerProxy`. Freedom outbounds are content-addressed (`frag-<hash>`), so entries with equal settings share one and a settings change changes the entry's own outbound — live apply and the stale-path sweeper need nothing new. A **master** keeps its dialer chain; its fragment goes on its slot's member outbounds instead (fragmenting inside the tunnel hides nothing), owner's setting first, then the first alias with one. Skipped where it can't work (UDP transports/protocols, a user-set `dialerProxy`, `tlshello` without TLS/REALITY); `fragmentNote` on the DTO says why. The tag must never start with `slot` — the burst observatory selects by that prefix.
- **An exit that closes on the ClientHello is a refusal, not silence.** FakeIP answers proxied names without an upstream lookup, so a name that doesn't exist (observed: stale `rr*---sn-*.googlevideo.com` hosts, NXDOMAIN everywhere) only fails at the exit — xray closes 3–8s later. If every member of a race round closes (`errUpstreamRefused`), the dial ends with `errDestinationRefused`: no retry rounds, and `tcpHealth.condemn` pauses the destination immediately so client retries fail in ~0s and a video player moves to another host. Mixed close + silence stays an ordinary failure. The verdict also needs one of the refusing members to have carried data within `refusalProofWindow` (`uplinkWitness.anyProven`): xray closes the same way when it can't reach its own server, so after a network change (uplink down, pool hosts unresolvable) or with a dead exit an unproven all-close round is an ordinary failure — otherwise every destination gets condemned up the pause ladder.
- **Members that share a way in are not independent.** Route keys ([daemon/routekeys.go](daemon/routekeys.go), published by the xray supervisor on every Reconcile): a master's key is its pool (`pool:` + sorted dialer refs — every master on one subscription shares it), any other entry/proxy is keyed by server host (port ignored). `raceRound` launches in `diverseOrder`, so the hedge goes to a different route before retrying one. Stickiness falls back from host to site (`siteKey`, e.g. `site:googlevideo.com`) so a new host of a known site starts on a proven member; a failure drops both bindings.
- **Proxy health resets only on a real network change** ([daemon/network_reset.go](daemon/network_reset.go)): the primary IPv4 route moved (interface/router/service), or the machine slept (wall clock ran past the monotonic clock). NOT on every network-watch event — DNS-config churn from our own hijack and VPN apps fires it constantly. A reset clears tcp/udp health and the latency tracker and kicks an immediate probe round; sticky bindings are kept.
- **Measure before tuning.** `connStats` ([daemon/connstats.go](daemon/connstats.go)) keeps a 15-minute window of proxied-connection outcomes — failures by cause (`no-upstream`, `no-data`, `paused`, `dial-ceiling`, `no-mapping`), setup-time histogram, extra (raced) attempts, UDP silent flows, per-upstream carried/blamed — and `health.stats` joins it with the breaker view, xray restart/live-apply counters and parked nodes. Surfaced on the Health tab (`ConnectionHealth.vue`) and as `em-wall health`. New failure paths in proxytun should record a cause.
- **Dead pool nodes are parked, not probed forever** ([daemon/xray_nodepark.go](daemon/xray_nodepark.go)). The generated config exposes xray's metrics endpoint on `xray.MetricsPort`; its `/debug/vars` `observatory` map is the only per-node health the CLI can't give. `PollNodeHealth` (30s) parks a node dead for `nodeDeadBeforePark` by leaving it out of its slot's members — the live apply turns that into one outbound removal — and returns it on trial after an exponentially growing park time (`nodeParkInitial` 5m → `nodeParkMax` 1h — short, because a parked node can never win traffic however well it would do). A real network change returns every parked node at once (`ReturnParked`). It never parks without a live sibling in the same slot (all-dead = uplink outage) and never empties a pool. Park state is in memory; a daemon restart simply re-trials everything. Every resolve prunes park records for keys no pool names any more (`retain`): a subscription refresh can re-key a node, and the old record otherwise cycled trial/park forever.
- **Pool health timeline** ([daemon/xray_timeline.go](daemon/xray_timeline.go)): `PollNodeHealth` now ticks every `nodeTimelineInterval` (10s) and records, per master pool, each member's probe state, balancer role (fallback / shortlisted / ranked out) and bytes moved since the last sample (xray's per-outbound counters, enabled via `policy.system.statsOutbound*`, read from the same `/debug/vars`) into a 30-min in-memory ring; parking and the shortlist still decide only every `nodeHealthPollInterval`. Rounds where no member answered are flagged `uplinkDown` and left out of every stat. Each pool also records its masters' set-ranking verdict per sample (`masterStanding`, from the latency tracker) plus every outage/demotion edge (`noteMasterEdge`, from the `OnSuspectChange`/`OnBreakerChange` hooks — edges, because a few-second outage falls between samples) with whether a carrying node was answering and whether the shortlist had been swapped within `nearSwapWindow`; each edge also writes an `xray pool: master … down — carrying nodes: …` log line. That split is the point: on the first real capture the pool nodes were steady while the masters on top flapped. Observation only. Exposed as `health.pools`, `em-wall health pools [MASTER] [--window]`, and the Health tab's Pool timeline.
- **Pool switch strategies** ([daemon/xray_strategy.go](daemon/xray_strategy.go), [core/xray/strategy.go](core/xray/strategy.go); ported from the sibling em-xray project, where they run in production). Per subscription (`Subscription.Strategy`, set only via `SetSubStrategy` / `xraysub.setStrategy`): `stable` = shortlist + parking as below; `agile` = no parking (entering agile un-parks the pool), and every 10s poll `agilePicker` points the balancer at the members alive right now (`agileAlive` = within `SlotBalancerTolerance`), cheapest last-RTT first, up to `agileActiveMax`, next live one as `DialerSlot.Fallback` — wired as `Preferred` costs + `Expected`; a carrying member that stops answering gets its masters' splices `markStale`d so the stall sweeper closes only the hung ones (no `ss -K` on macOS); `manual` = the slot's Members are exactly the pinned nodes (`SubNodeOverride.Pinned`; a pin is active past the node cap, pinning enables, disabling unpins), a pinless manual pool runs stable; `auto` (default) = `autoClassifier` reads the pool timeline over `autoWindow` and goes agile on `autoPickLosses` pick losses or `autoFlappingPct` of nodes (≥`autoMinFlapping`) flipping `autoFlips`+ times, back to stable after `autoCalm` quiet; in memory. A pool on several subscriptions: manual if any is manual, else agile if any agile, else auto if any auto, else stable; an entries-only pool is auto. Keyed by `DialerSlot.PoolKey` (sorted dialer refs). Strategy travels in export bundles; pins don't.
- **A passing health ping doesn't prove a pool node can carry a master** ([daemon/xray_pathprobe.go](daemon/xray_pathprobe.go)). The observatory's generate_204 is a few hundred bytes. Observed on a filtering home ISP: raw-TCP VLESS nodes moved 7–13 KB per connection and then stalled (they worked on cellular). They answered the ping fastest, so the shortlist put every master on them. The daemon now tests the real path through a password-auth SOCKS **probe inbound** (`xray.ProbePort`; xray routes by SOCKS username, so one port reaches every outbound). Each round tests a slot's carriers plus `pathProbeCandidates` due members, two ways: a `netprobe.MeasureDownload` of `DownloadTestBytes` through the member, and a URL test through each slot master chained over that one member (`xray.ChainProbeTag`, a copy of the master's outbound with `dialerProxy` = the member). A failure is a strike only if, in the same round, another member passed the same test (for a chain, the same master through a member that isn't choking). That way a dead uplink or a broken master config blames no node. After `pathStrikes` strikes the member is `DialerSlot.Broken`, which means: it costs `slotBrokenCost` (sorted behind even demoted members), it is never the fallback, and the shortlist (`dropBroken`) and the agile pick skip it. All of this is skipped when every member is broken. One pass clears it. Verdicts reset on a real network change. The set prober does the same for set members: every `proxyTransferEvery`-th full round, a member that passes the URL test must also finish the transfer, or the whole round counts as failures.
- Dialer-slot balancers spread over the best `slotBalancerExpected` (2) members and carry a `fallbackTag` (first member): without it a fresh slot has no observatory data for ~one probe interval and every master connection fails.
- **The daemon, not leastLoad, decides which pool nodes carry a master** ([daemon/xray_shortlist.go](daemon/xray_shortlist.go)). xray's leastLoad sorts by RTT *deviation* first, so on its own it picks the steadiest nodes, not the fastest. `PollNodeHealth` scores each member from the observatory window (average + deviation, × failure rate) and names the best `SlotShortlistSize` as `DialerSlot.Preferred`, with hysteresis; `Generate` turns that into stock leastLoad `costs` (shortlist cost 1, everything else `slotDemotedCost`, √-scaled by xray) and makes the shortlist head the `fallbackTag`. Demoted members stay eligible, so xray's ping-by-ping failover is kept, and a new shortlist is a routing-only live apply. Seats are judged on a smoothed score (`shortlistSmoothing` EWMA): on raw scores one lost ping (×1.33) cleared the 25% margin and the second seat changed hands every 30–60s; qualification still uses the raw window, so a really failing node loses its seat at once. `SlotBalancerTolerance` (0.5 of a 6-ping window) must stay loose: on a lossy uplink every node loses 2–3 of 6, and a tolerance that excludes all of them collapses the slot onto its fallback. Never fork xray for selection logic — steer it through generated config.
- **Set members are also judged per site, by exit, and on real traffic.** `siteAvoid` ([daemon/siteavoid.go](daemon/siteavoid.go)) ranks a member that failed one site `siteAvoidStrikes` times behind its siblings *for that site* (an exit-IP ban looks healthy everywhere else); cleared the moment it answers or carries data there, never an exclusion. `exitKeys` ([daemon/exitkeys.go](daemon/exitkeys.go)) measures each multi-binding member's exit IP via ip-api every 15 min (sequential, rate-limited — shares the free tier with the UI's exit lookups) and feeds it to both `diverseOrder` (a hedge must share neither route nor exit) and `siteAvoid` (a ban on an exit avoids every member behind it). `LatencyTracker.ObserveHandshake` ([core/netprobe/handshake.go](core/netprobe/handshake.go)) takes ClientHello→first-byte times from `raceRound` (winner, plus still-waiting losers as lower bounds) and keeps only the ratio to that destination's recent norm across members — raw times would just measure how far each member's sticky sites are — which scales the probe RTT in `sample.cost` by at most [0.5, 3].
- **A subscription node can be promoted to a standalone entry, as a copy.** Pool nodes are only reachable through a master entry's `Dialer`; `xraysub.importNode` ([daemon/xray_import.go](daemon/xray_import.go)) copies one node's outbound into an ordinary `xray.Config` so a rule can target it as `xray:NAME` and a set can list it as a member. It must be a copy, not a reference: `ReplaceNodes` wipes and rebuilds a subscription's pool on every fetch, so a referencing entry would break whenever the provider reordered its list. The entry keeps only the origin (`SubID` + `SubFingerprint`) — enough to mark the node as already promoted in the panel and to flag the entry `SourceGone` once its node stops appearing. `Store.Update` writes an explicit field list, which is what keeps an edit or rename from erasing that origin. Names come from `xray.SuggestName` (provider names are emoji-laden and collide once stripped to the entry charset) and are deduped by `uniqueXrayName`.
- Adding patterns to a curated group in `core/groups` does **not** reach users who already applied that group — their rules are rows in the DB. `groups.list` reports the gap per group as `MissingPatterns`, and `groups.sync` ([daemon/groups_sync.go](daemon/groups_sync.go)) inserts only those, copying the action/interface of the group's existing rules. The UI surfaces it as a "+N new" pill and a Sync / Sync all button. So: extend a group's pattern list freely, no migration needed.
- Settings live in the same SQLite DB as rules (key/value table), accessed via `store.GetSetting/SetSetting`. Stateful daemon decisions (`block_encrypted_dns`, `system_dns_active`, `upstream_dns`, `system_dns_backup`) round-trip through here.
- `MethodSettingsSet` has a side-effect for `block_encrypted_dns`: it calls `pf.Sync` to install/remove the anchor. New side-effecting settings keys go in the same handler.
